# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс `Component`

Абстрактный базовый класс для компонентов интерфейса. Параметр `T` задаёт тип данных, принимаемых методом `render`.

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

- `protected constructor(container: HTMLElement)` — принимает корневой DOM-элемент компонента.

**Поле**

- `protected readonly container: HTMLElement` — хранит корневой DOM-элемент компонента.

**Методы**

- `render(data?: Partial<T>): HTMLElement` — копирует переданные данные в экземпляр компонента и возвращает корневой DOM-элемент.
- `protected setImage(element: HTMLImageElement, src: string, alt?: string): void` — задаёт изображению источник и, если передан, альтернативный текст.

#### Класс `Api`

Класс содержит базовую логику отправки HTTP-запросов.

**Конструктор**

- `constructor(baseUrl: string, options: RequestInit = {})` — принимает базовый адрес сервера и необязательные параметры запроса.

**Поля**

- `readonly baseUrl: string` — базовый адрес сервера.
- `protected options: RequestInit` — параметры запросов, включая заголовки.

**Методы**

- `get<T extends object>(uri: string): Promise<T>` — выполняет GET-запрос и возвращает типизированный ответ сервера.
- `post<T extends object>(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<T>` — отправляет данные в JSON-теле запроса; метод запроса по умолчанию — `POST`.
- `protected handleResponse<T>(response: Response): Promise<T>` — возвращает данные успешного ответа или отклоняет промис при ошибке.

#### Класс `EventEmitter`

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

**Конструктор**

- Не принимает параметров.

**Поле**

- `_events: Map<EventName, Set<Subscriber>>` — хранит подписчиков, сгруппированных по имени события или регулярному выражению. `EventName` — `string | RegExp`, `Subscriber` — функция.

**Методы**

- `on<T extends object>(eventName: EventName, callback: (event: T) => void): void` — подписывает обработчик на событие.
- `off(eventName: EventName, callback: Function): void` — снимает обработчик с события.
- `emit<T extends object>(eventName: string, data?: T): void` — вызывает обработчики события и передаёт им данные.
- `onAll(callback: (event: { eventName: string; data: unknown }) => void): void` — подписывает обработчик на все события.
- `offAll(): void` — удаляет все подписки.
- `trigger<T extends object>(eventName: string, context?: Partial<T>): (event?: object) => void` — создаёт функцию, которая при вызове инициирует событие с объединёнными данными и контекстом.

### Типы данных

- `TPayment` — допустимые способы оплаты: `card` и `cash`.
- `IProduct` — данные одного товара.
- `IBuyer` — контактные данные покупателя и способ оплаты.
- `IOrder` — данные покупателя, массив id товаров и общая сумма заказа для отправки на сервер.
- `IProductListResponse` — ответ сервера со списком товаров и их количеством.
- `IOrderResponse` — ответ сервера с id заказа и итоговой суммой.

## Модели данных

### Класс `Products`

Хранит каталог товаров и товар, выбранный для просмотра.

**Конструктор**

- Не принимает параметров.

**Поля**

- `items: IProduct[]` — массив товаров каталога.
- `selectedProduct: IProduct | null` — выбранный товар или `null`, если товар не выбран.

**Методы**

- `setItems(items: IProduct[]): void` — сохраняет массив товаров.
- `getItems(): IProduct[]` — возвращает каталог.
- `getItem(id: string): IProduct | undefined` — ищет и возвращает товар по id. Если товар не найден, возвращает `undefined`.
- `setSelectedProduct(product: IProduct): void` — сохраняет товар для просмотра.
- `getSelectedProduct(): IProduct | null` — возвращает выбранный товар или `null`.

### Класс `Basket`

Хранит товары, выбранные покупателем.

**Конструктор**

- Не принимает параметров.

**Поле**

- `items: IProduct[]` — массив товаров в корзине.

**Методы**

- `getItems(): IProduct[]` — возвращает товары в корзине.
- `addItem(item: IProduct): void` — добавляет товар, если этого id ещё не находится в корзине.
- `removeItem(id: string): void` — удаляет товар по id.
- `clear(): void` — очищает корзину.
- `getTotal(): number` — возвращает общую стоимость товаров; товар с `price: null` учитывается как 0.
- `getCount(): number` — возвращает количество товаров.
- `hasItem(id: string): boolean` — проверяет, есть ли товар с указанным id в корзине.

### Класс `Buyer`

Хранит данные покупателя, которые заполняются при оформлении заказа.

**Конструктор**

- Не принимает параметров.

**Поле**

- `data: Partial<IBuyer>` — заполненные на данный момент данные покупателя. Поля можно сохранять постепенно.

**Методы**

- `setData(data: Partial<IBuyer>): void` — добавляет или обновляет переданные данные, сохраняя остальные ранее заполненные поля.
- `getData(): Partial<IBuyer>` — возвращает копию сохранённых данных.
- `clear(): void` — очищает данные покупателя.
- `validate(fields?: (keyof IBuyer)[]): Partial<Record<keyof IBuyer, string>>` — проверяет выбранные поля. Если список `fields` не передан, проверяются все поля. Возвращает объект с сообщениями об ошибках. Если ошибок нет, возвращает пустой объект.

## Слой коммуникации

### Класс `ShopApi`

Выполняет запросы к серверу: получает каталог товаров и отправляет заказ. Для запросов использует переданный API-клиент, соответствующий интерфейсу `IApi`.

**Конструктор**

- `constructor(api: IApi)` — принимает API-клиент.

**Поле**

- `api: IApi` — хранит API-клиент. Поле закрыто для внешнего доступа и не может быть переназначено.

**Методы**

- `getProductList(): Promise<IProductListResponse>` — выполняет GET-запрос к `/product/` и возвращает список товаров.
- `createOrder(order: IOrder): Promise<IOrderResponse>` — отправляет заказ POST-запросом к `/order/` и возвращает ответ сервера.
